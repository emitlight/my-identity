# 기술 아키텍처

## 1. 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | **Next.js 15 (App Router) + TypeScript** | 서버 컴포넌트로 초기 로딩이 빠르고, API Route가 알림 발송·크론 엔드포인트를 겸한다. 앱 하나로 끝난다. |
| 호스팅 | **Vercel** | 비공개 레포에서 push → 자동 배포. 무료 티어로 충분. 커스텀 도메인 무료. |
| DB / 인증 / 스토리지 | **Supabase** | Postgres + Google OAuth + 파일 저장 + 실시간 + RLS를 하나로. 개인 대시보드 규모에서 무료 티어 여유. |
| UI | **Tailwind CSS + shadcn/ui** | 모바일 우선. 컴포넌트를 코드로 소유해서 자유롭게 고친다. |
| 상태/데이터 | **TanStack Query + Server Actions** | 낙관적 업데이트로 체크박스가 즉시 반응 (지연 = 안 쓰게 됨) |
| 지도 | **Leaflet + OSM** (→ 필요 시 Kakao Map) | 무료·키 불필요로 시작. 국내 장소 정확도가 문제되면 카카오맵으로 교체. |
| 푸시 | **Web Push (VAPID) + Service Worker** | 외부 서비스 가입 없이 무료. iOS 16.4+ / Android 지원. |
| PWA | **manifest + SW + 오프라인 캐시** | 홈 화면 설치 = 습관화. iOS는 설치해야 푸시가 동작. |
| 스케줄러 | **GitHub Actions cron → API Route** | Vercel Hobby 크론은 하루 1회 제한. Actions는 무료로 5분 단위. |

### 왜 Vercel + Supabase인가
개인 대시보드에서 진짜 비용은 서버비가 아니라 **내가 유지보수에 쓰는 시간**이다. 인증·DB·스토리지·실시간·보안을 각각 붙이면 그걸 붙이다 끝난다. Supabase 하나로 묶으면 첫 화면까지 가장 빠르고, Postgres라서 나중에 어디로든 이전할 수 있다 (락인 없음).

## 2. 캘린더 — 앱 안에서 직접 넣고 본다

**서비스가 일정의 원본(source of truth)이다.** 구글 캘린더가 없어도 완결되고, 구글 연동은 선택적 미러링일 뿐이다.

> 일정이 이 DB 안에 있어야 **맥락 서피싱이 동작한다.** 외부 캘린더에만 있으면 "대전 출장 → 대전 맛집 카드"를 만들 수 없다. 캘린더를 직접 갖는 건 편의 문제가 아니라 구조 문제다.

### 2-1. 입력 — 넣기가 귀찮으면 안 넣는다

3단계로 제공하고, **기본은 자연어**다.

**① 자연어 한 줄 (기본)**
```
"내일 오후 3시 강남 미팅 2시간"
   → 2026-09-13 15:00~17:00 · 장소: 강남 · 제목: 미팅

"매주 목요일 저녁 7시 골프 레슨"
   → 매주 목 19:00 반복 · 역할: 골퍼(자동 매칭)

"11월 20일 대전 출장"
   → 종일 일정 · region: 대전  ← 맛집 컬렉션 트리거 발동
```
파싱 결과를 **저장 전에 칩(chip) 형태로 보여주고 탭해서 수정**한다. 틀린 파싱을 고치는 비용이 폼 작성보다 싸야 한다.
(Phase 1: 한국어 규칙 기반 파서 / Phase 2: LLM 파싱으로 정확도 상승)

**② 캘린더에서 드래그** — 주간 뷰에서 시간대를 끌면 일정 생성

**③ 상세 폼** — 역할·프로젝트·장소·반복·알림·준비 할 일까지

### 2-2. 뷰

| 뷰 | 화면 | 기본 |
|---|---|---|
| **어젠다** (리스트) | 모바일 | ✅ 모바일 기본 — 스크롤로 앞뒤를 본다 |
| **주간** | 데스크탑 | ✅ 데스크탑 기본 — 타임블록 |
| **월간** | 공통 | 큰 그림 |
| **일간** | 공통 | 일정 많은 날 |

**역할별 색**으로 칠해지므로, 월간 뷰를 보면 *"이번 달 온통 사업가 색이고 골퍼 색이 하나도 없다"* 가 한눈에 보인다. 이게 아이덴티티 대시보드의 캘린더가 일반 캘린더와 다른 점이다.

### 2-3. 할 일과 통합
`tasks.scheduled_for`가 있는 할 일은 캘린더에 **연한 블록**으로 함께 표시된다. 일정과 할 일을 다른 앱에서 보면 하루 용량을 오판하게 된다. 드래그해서 시간을 배정하면 타임블록킹이 된다.

### 2-4. 일정에서 번져나가는 것들
- 미팅 일정 → **회의록 메모 자동 생성** (일정에 연결됨)
- 장소 있는 일정 → **맥락 카드 트리거** (§ DESIGN 4-3)
- 일정 종료 후 → *"어땠나요"* 푸시 → 한 줄 기록
- 반복 일정 → 습관으로 승격 제안

### 2-5. 구글 캘린더 (Phase 3, 선택)
읽기 전용 가져오기부터. 양방향은 충돌 처리가 복잡해서 나중에 판단한다. `events.source`/`external_id`가 이미 준비되어 있다.

## 3. 푸시 알림 파이프라인

```
GitHub Actions cron (*/10 * * * *)
        │  POST + CRON_SECRET 헤더
        ▼
/api/cron/tick  ── notification_rules 평가
        │         ├─ 시각 도달?
        │         ├─ 조건 충족? (습관 미체크, 마감 임박, 일정 30분 전…)
        │         └─ 중복 발송 방지 (notifications 테이블 조회)
        ▼
web-push (VAPID) → push_subscriptions 전체 기기
        ▼
Service Worker → 알림 표시 → 탭 → 해당 화면으로 딥링크
```

**iOS 주의**: Safari에서 **"홈 화면에 추가"를 해야만** 웹 푸시가 동작한다. 최초 설정 화면에서 이걸 안내하는 단계를 반드시 넣는다 (이게 없으면 "알림이 안 와요"로 끝난다).

**만료 구독 정리**: 발송 시 410/404가 오면 해당 `push_subscriptions` 행을 삭제한다.

## 4. 보안

| 층 | 조치 |
|---|---|
| 인증 | Supabase Auth · Google OAuth · **허용 이메일 화이트리스트** (`ALLOWED_EMAILS`) |
| 인가 | 전 테이블 RLS `user_id = auth.uid()`. 마이그레이션에 정책 포함, 테스트로 검증 |
| API | 서버 액션/라우트에서 세션 재검증. 클라이언트 신뢰 안 함 |
| 크론 | `CRON_SECRET` 헤더 대조. 없으면 404 |
| 시크릿 | Vercel 환경변수. **service_role 키는 서버 전용** (절대 `NEXT_PUBLIC_` 금지) |
| 백업 | 주 1회 전체 JSON export → Supabase Storage (+ 다운로드 버튼) |

### 환경변수
```
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY      # 서버 전용
NEXT_PUBLIC_VAPID_PUBLIC_KEY
VAPID_PRIVATE_KEY              # 서버 전용
CRON_SECRET                    # 서버 전용
ALLOWED_EMAILS                 # 쉼표 구분
```

## 6. 성능 — "느리면 안 쓴다"

- Today 화면은 **단일 RPC**로 필요한 것만 가져온다 (테이블마다 쿼리 날리지 않는다)
- 체크박스·습관 체크는 **낙관적 업데이트** — 서버 응답을 기다리지 않는다
- 목표: 폰에서 Today **1.5초 이내** 표시
- 컬렉션 목록은 커서 페이지네이션, 지도는 뷰포트 내 항목만
