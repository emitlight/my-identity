# My Identity — 제품 설계서

> 흩어진 나의 모든 것을 한 화면으로 모으고, **적절한 순간에 알아서 꺼내주는** 개인 대시보드.

---

## 1. 문제 정의 — 왜 노션은 실패했는가

사용자의 말: *"노션에 데이터를 너무 많이 담아놨는데 아무래도 잘 들어가게 되지 않는다."*

이건 **기능 부족 문제가 아니다.** 노션은 기능이 남아돈다. 실패 원인은 셋이다.

| 원인 | 증상 | 이 대시보드의 해법 |
|---|---|---|
| **입력 마찰** | 메모 하나 쓰려면 워크스페이스 → 페이지 → DB → 속성 채우기. 5단계. | 홈 최상단 고정 입력창. 한 줄 쓰고 엔터. 분류는 나중에. |
| **복귀 동력 없음** | 내가 먼저 열지 않으면 노션은 영원히 조용하다. | 푸시가 나를 부른다. 알림 → 탭 → 이미 할 일이 화면에 있다. |
| **탐색 비용** | "그 자료 어디 뒀더라" → 찾다가 포기. | 찾지 않는다. **맥락에 맞춰 알아서 올라온다.** |

> **핵심 통찰**: 기능을 더 넣으면 똑같이 안 쓰게 된다. 마찰을 줄이고 동력을 넣어야 한다.

---

## 2. 설계 원칙

1. **입력은 3초 안에 끝난다.** 어떤 화면에서든 `빠른 캡처`가 한 탭 거리에 있다. 제목만 있어도 저장된다. 미분류 항목은 나중에 정리하면 되고, 정리하지 않아도 시스템은 망가지지 않는다.
2. **첫 화면에서 종결된다.** `Today`를 열면 "지금 뭐 하지"에 대한 답이 나와 있다. 탐색해서 찾아내는 구조를 만들지 않는다.
3. **푸시가 앱을 연다.** 알림 없는 대시보드는 반드시 버려진다. 알림은 "알림을 위한 알림"이 아니라 *행동 가능한 것*만 보낸다.
4. **자료는 탄약이다.** 저장된 자료는 읽히기를 기다리지 않는다. 일정·위치·요일·날씨에 맞춰 스스로 Today에 올라온다.
5. **완벽한 분류를 요구하지 않는다.** 태그 안 달아도, 프로젝트 연결 안 해도 동작한다. 구조를 강요하는 순간 다시 안 쓰게 된다.

## 3. 정보 구조 — 3층 모델

```
┌──────────────────────────────────────────────────────┐
│  Layer 1 — TODAY  (실행층)          매일 본다        │
│  오늘 일정 · 오늘 할 일 · 습관 체크 · 맥락 카드      │
│  ＋ 빠른 캡처                                        │
└──────────────────────────────────────────────────────┘
            ▲ 올라온다                 ▼ 떨어진다
┌──────────────────────────────────────────────────────┐
│  Layer 2 — DOMAINS  (관리층)        주 1~2회 본다    │
│  일정 · 할일/프로젝트 · 메모 · 컬렉션 ·              │
│  비즈니스 · 기록/지표                                │
└──────────────────────────────────────────────────────┘
            ▲ 근거가 된다             ▼ 방향을 준다
┌──────────────────────────────────────────────────────┐
│  Layer 3 — IDENTITY CORE  (기준층)  월/분기에 본다   │
│  가치 · 역할 · 목표(연/분기/월) · 회고               │
└──────────────────────────────────────────────────────┘
```

**층마다 보는 주기가 다르다.** 이게 노션 대시보드와 결정적으로 다른 점이다. 노션은 모든 걸 같은 깊이에 평평하게 놓아서, 매일 볼 것과 분기에 한 번 볼 것이 섞여 인지 부하를 만든다.

### Layer 3 — Identity Core (기준층)
내가 누구이고 어디로 가는가. **역할(Role)** 단위로 삶을 나눈다 — 예: `사업가` `개발자` `골퍼` `아들`. 모든 목표·프로젝트·할 일은 역할에 연결되고, 색으로 구분된다. 이게 "나의 아이덴티티"를 대시보드가 실제로 표현하는 방식이다.

주간 회고에서 *"이번 주 역할별 시간 배분"* 을 보여주면 — 사업가 80%, 골퍼 0%, 아들 0% — 말이 아니라 데이터로 삶의 불균형이 드러난다.

### Layer 2 — Domains (관리층)
실제 데이터가 사는 곳. 일정, 할 일, 메모, **컬렉션**, 비즈니스, 기록.

### Layer 1 — Today (실행층)
Layer 2에서 *오늘 필요한 것만* 끌어올린 화면. 직접 데이터를 갖지 않고, 전부 파생된다.

**Today 화면 구성 (위→아래 순):**
1. 빠른 캡처 입력창 (항상 최상단 고정)
2. 지금 시각 기준 다음 일정
3. 오늘의 할 일 (3~5개로 제한 — 더 보여주면 압도되어 안 본다)
4. 습관 체크 (탭 한 번)
5. **맥락 카드** — 오늘 상황에 맞는 컬렉션/메모가 자동으로 올라오는 자리
6. 한 줄 회고 (밤에 푸시로 유도)

## 4. 컬렉션 시스템 — 흩어진 자료를 담는 법

### 4-1. 왜 블로그/매거진이 아닌가

"대전 맛집 페이지", "수도권 골프장 리스트" 같은 자료를 **글(post)로 저장하면 노션의 실패를 반복한다.** 글은 읽으러 들어가야 하는데, 안 들어가니까.

이 자료의 실제 쓰임새는 **읽기**가 아니라 **결정**이다:
- *"오늘 대전 출장인데 저녁 어디 가지"*
- *"이번 주말 골프 어디로 잡지"*

결정을 도우려면 **필터되고, 정렬되고, 지도에 찍히고, 가본 곳은 표시되어야** 한다. 글 덩어리로는 불가능하다.

### 4-2. 해법 — 구조로 저장, 4가지로 보기

**저장은 구조화된 레코드로:**

| 컬렉션 | 공통 필드 | 타입별 필드 (유연 스키마) |
|---|---|---|
| 대전 맛집 | 이름·좌표·주소·태그·평점·방문여부·한줄평·사진 | 가격대, 주차, 예약필요, 대표메뉴, 영업시간 |
| 수도권 골프장 | 〃 | 홀수, 그린피(주중/주말), 캐디, 부킹난이도, 집에서 거리 |
| 읽을 책 | 〃 | 저자, 페이지, 읽은 날짜, 인상 깊은 구절 |

공통 필드는 정규 컬럼으로, 타입별 필드는 `JSONB`로 둔다. 컬렉션 정의(`schema`)에 필드 목록이 들어 있어서 **입력 폼과 필터 UI가 자동 생성된다.** 새 컬렉션을 만들어도 코드를 안 고쳐도 된다.

**보기는 4가지 뷰로 전환:**

| 뷰 | 언제 쓰나 |
|---|---|
| 🗺 **지도** | "지금 이 근처 뭐 있지" — 맛집·골프장의 기본 뷰 |
| ▤ **리스트/필터** | "주차 되고 4인 이상 되는 곳" — 조건으로 좁힐 때 |
| ▢ **카드** | 사진 보면서 고를 때 |
| 📖 **매거진** | 훑어보고 싶을 때 — 원하셨던 잡지 느낌이 여기 |

그리고 **항목 상세 페이지**(`/collections/daejeon-food/{item}`)는 사진 + 마크다운 본문이 들어가는 **풍성한 매거진형 페이지**다. 블로그 글의 감성은 여기서 완전히 살린다.

> **정리: 매거진은 저장 형식이 아니라 보기 형식이다. 구조로 저장하면 매거진도 되고 지도도 되지만, 글로 저장하면 글밖에 안 된다.**

### 4-3. 진짜 차별점 — 맥락 서피싱 (Context Surfacing)

여기가 노션으로 **절대 불가능한** 부분이고, 이 프로젝트의 존재 이유다.

```
캘린더에 "대전 출장" (11/20)
          │
          ▼  트리거: 일정 위치에 '대전' 포함
11/20 아침 07:30 푸시 →  "오늘 대전이네요. 저장해둔 맛집 3곳이 아직 미방문입니다"
          │
          ▼  탭
Today 화면 상단에 【대전 맛집 · 미방문 3】 카드 → 지도 열기 → 결정
          │
          ▼  다녀온 뒤
알림에서 바로 "방문 체크 + 한 줄 평" → 다음 추천 품질이 올라감
```

**트리거 예시:**

| 트리거 | 올라오는 것 |
|---|---|
| 일정 장소에 지역명 매칭 | 해당 지역 맛집/카페 컬렉션 |
| 토요일 아침 | 골프장 컬렉션 + 날씨 |
| 이동 중(위치) | 근처 미방문 항목 |
| 오래 안 본 컬렉션 | "이 자료 3개월째 안 보셨어요" |
| 비즈니스 미팅 일정 | 해당 고객 메모 + 지난 미팅 기록 |

자료가 **나를 기다리지 않고 나를 찾아온다.** 이게 "실속 있는 대시보드"의 실체다.

### 4-4. 자료 투입 방법

| 단계 | 방법 |
|---|---|
| **Phase 1 (지금)** | 대화로 원문을 주시면 → 제가 구조화 → seed 파일로 DB 투입. 노션 커넥터 연결 시 기존 DB 자동 마이그레이션. |
| **Phase 2** | 앱 안에 `붙여넣기 → 자동 구조화` 입력창. 텍스트 덩어리를 붙이면 LLM이 행으로 쪼개 준다. |
| **Phase 3** | URL 붙여넣기 → 메타데이터·사진·좌표 자동 수집 |

## 5. 비서 엔진 — 나에게 말 거는 대시보드

알림은 **행동 가능한 것만.** 정보성 알림은 무시하는 법을 학습시키고, 그러면 진짜 중요한 알림도 무시하게 된다.

| 시각 | 알림 | 행동 |
|---|---|---|
| 07:30 | **아침 브리핑** — 오늘 일정 N건, 할 일 N건, 첫 일정까지 N시간 + 맥락 카드 | 탭 → Today |
| 일정 전 | 30분 전 리마인더 (이동시간 있으면 그만큼 앞당김) | 탭 → 일정 상세 |
| 12:00 | 습관 미체크 시에만 | 알림에서 바로 체크 |
| 21:30 | **저녁 회고** — "오늘 어땠나요" 한 줄 + 기분 1~5 | 알림에서 바로 입력 |
| 일 09:00 | **주간 리뷰** — 역할별 시간 배분, 목표 진척, 다음 주 미리보기 | 탭 → 리뷰 |
| 상시 | 마감 임박, 오래 방치된 항목 | 탭 → 해당 항목 |

**모든 알림에 "왜 지금 이게 왔는지"가 한 줄로 들어간다.** 이유 없는 알림은 끄게 된다.

## 6. 보안 — 비공개 레포로 배포해도 접근 가능한가

**가능하다.** 세 가지가 완전히 분리되어 있다.

| 층 | 통제 대상 | 설정 |
|---|---|---|
| GitHub 레포 **비공개** | 소스 코드를 누가 보는가 | 배포와 무관. Vercel은 비공개 레포도 정상 빌드 |
| 앱 **로그인** | 데이터를 누가 보는가 | Google OAuth + 허용 이메일 화이트리스트 |
| Supabase **RLS** | DB가 누구 행을 내주는가 | 모든 테이블에 `user_id = auth.uid()` 정책 |

접속 흐름: `https://내도메인.com` → 로그인 → 대시보드. 폰·회사 노트북 어디서든 **URL + 본인 계정 인증**만으로 접근된다.

> ⚠️ URL 자체는 공개이므로 로그인 화면까지는 누구나 온다. 따라서 **앱 인증과 RLS를 반드시 함께** 건다. RLS는 API 키가 유출돼도 남의 데이터가 안 나가게 하는 마지막 방어선이다.

데이터는 Supabase(클라우드 Postgres)에 살기 때문에 레포·배포·이 세션과 무관하게 영구 보존된다. 주간 자동 백업(JSON export → 저장소)도 넣는다.
